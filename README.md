# ClockHub

A free online **Alarm Clock, Countdown Timer, Stopwatch and World Clock**, live at
**[clock-hub.com](https://clock-hub.com)**.

Built with plain HTML, CSS and JavaScript. No frameworks, no build step, no backend,
no dependencies. Every page is a single self-contained file with its CSS, JavaScript
and logo inlined, so there is nothing to break during deployment.

## Pages

| File | URL | Purpose |
|---|---|---|
| `index.html` | `/` | Alarm clock (home page) |
| `timer.html` | `/timer.html` | Countdown timer |
| `stopwatch.html` | `/stopwatch.html` | Stopwatch with lap times |
| `clock.html` | `/clock.html` | Current time and world clock |
| `404.html` | any missing URL | Not-found page |

## Features

**Alarm clock** with hour/minute/AM-PM pickers, twelve quick presets, three alarm
sounds generated by the Web Audio API (no audio files to load), a test button, a
full-screen ringing overlay and recently used alarm times saved in the browser.

**Countdown timer** driven by real clock time rather than frame counting, so it stays
accurate in background tabs. Pause and resume, twelve presets, alarm and browser
notification when the countdown reaches zero.

**Stopwatch** accurate to a hundredth of a second with a lap table and keyboard
shortcuts: Space to start and pause, L to record a lap, R to reset.

**World clock** showing live time in twelve cities, US time zones first. Visitors can
add any city in the world through a country and time zone picker, and their choices
are remembered in the browser.

Plus a dark and light theme that is saved between visits, a fullscreen mode, and live
tab-title updates while a timer or stopwatch is running.

## SEO

Each page ships with a unique title and meta description, a canonical URL, Open Graph
tags, `hreflang` and US geo hints, and JSON-LD structured data covering `WebSite`,
`WebApplication`, `BreadcrumbList` and `FAQPage`. Around 4,700 words of original
content sit across the four pages, along with `sitemap.xml`, `robots.txt`, semantic
headings and internal linking.

## Deploying with GitHub Pages

1. Create a new repository and push these files to the **root** of the default branch
   (not inside a subfolder).
2. In the repository, open **Settings → Pages**.
3. Under **Build and deployment**, set **Source** to *Deploy from a branch*, pick your
   branch and the `/ (root)` folder, then save.
4. Under **Custom domain**, enter `clock-hub.com` and save. The `CNAME` file in this
   repository already contains that value.
5. Point your domain's DNS at GitHub Pages. For an apex domain like `clock-hub.com`
   you need four `A` records (and optionally the matching `AAAA` records) pointing at
   GitHub's Pages IP addresses, plus a `CNAME` record for `www` pointing to
   `<your-username>.github.io`. GitHub publishes the current IP addresses here:
   <https://docs.github.com/pages/configuring-a-custom-domain-for-your-github-pages-site>
   Use the values from that page rather than copying them from anywhere else, since
   they can change.
6. Once DNS has propagated, tick **Enforce HTTPS** in Settings → Pages.

DNS changes can take anywhere from a few minutes to a couple of hours to take effect.

## Files explained

- `.nojekyll` — stops GitHub Pages from running the site through Jekyll, which would
  otherwise ignore files and folders whose names begin with an underscore.
- `CNAME` — tells GitHub Pages which custom domain serves this site.
- `.htaccess` — Apache configuration for HTTPS and non-www redirects. Ignored by
  GitHub Pages and Netlify; useful if you move to cPanel or another Apache host.
- `_redirects` — Netlify redirect rules. Ignored by GitHub Pages; useful if you deploy
  to Netlify instead.
- `.gitignore` — keeps OS junk files out of the repository.

## Deploying somewhere else

**Netlify or Vercel:** connect the repository, leave the build command empty and set
the publish directory to the repository root. `_redirects` and `404.html` are picked
up automatically.

**cPanel or other Apache hosting:** upload every file to `public_html`, including the
hidden files. In cPanel's File Manager, turn on *Settings → Show Hidden Files* so
`.htaccess` is visible and uploaded.

## Checklist after going live

1. Confirm `https://clock-hub.com` loads and that `http://` and `www.` both redirect
   to it.
2. Open each of the four pages and check the alarm, timer, stopwatch and world clock.
3. Add the site to [Google Search Console](https://search.google.com/search-console)
   and submit `https://clock-hub.com/sitemap.xml`.
4. Run a page through the
   [Rich Results Test](https://search.google.com/test/rich-results); FAQ and
   Breadcrumb should both be reported as eligible.
5. Add a Privacy Policy page before applying to Google AdSense, which requires one.

## Changing the domain

Replace `clock-hub.com` in all five HTML files plus `sitemap.xml`, `robots.txt`,
`CNAME`, `.htaccess` and `_redirects`.
